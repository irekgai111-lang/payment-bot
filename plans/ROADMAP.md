# Roadmap — Service Upgrade System

## ✅ Уже сделано

- Выбор одного из двух вариантов продукта через inline-кнопки
- Показ реквизитов карты Visa с суммой
- SQLite БД `payments.db` (таблица `payments` с user_id, name, username, product_name, amount, status, created_at)
- Уведомление админа о новом клиенте и об оплате
- Автоматическая отдача `guide.pdf` после клика «Я оплатил»
- Команда `/stats` для админа (pending count + сумма)
- Команда `/help` со списком вариантов и контактами
- Rate limiting 5 сек между callback-запросами
- PID-lock против двойного запуска (`bot.pid`)
- `.gitignore` закрывает `.env`, `payments.db`, `bot_logs.log`, `bot.pid`

## 🔴 Срочно (блокеры запуска)

- [ ] Положить реальный `guide.pdf` в корень проекта (сейчас лежит только `README_GUIDE.txt`-заглушка)
- [ ] Отозвать старый BOT_TOKEN через `@BotFather` → `/revoke`; новый уже в `.env`
- [ ] `pip install -r requirements.txt` на машине запуска
- [ ] End-to-end прогон: `/start` → выбор → реквизиты → «Я оплатил» → получение PDF → проверка записи в `payments.db`

## 📌 Технический долг

- `user_products` и `user_last_request` хранятся в памяти — при рестарте теряются. Перенести в SQLite (таблица `sessions`).
- В `bot.py` нет хэндлера на любые «прочие» сообщения — клиент может зависнуть, если напишет текст вместо кнопки. Добавить fallback-handler с подсказкой.
- `fmt_card()` хардкодит длину 16 символов — упадёт на нестандартных номерах. Сделать защиту по длине.
