# Operations — ежедневная эксплуатация бота

Документ для оператора (владельца бота). Объясняет, что нужно делать каждый день, чтобы бот работал, и как проверить, что всё в порядке.

## TL;DR — что делать каждый день

**Ничего.** Просто включай ноутбук как обычно. Бот стартует сам.

## Сценарий «каждое утро»

1. Нажимаешь кнопку питания на ноутбуке
2. Windows загружается (30–60 сек)
3. Входишь в Windows (PIN/пароль/biometric — без разницы)
4. Появляется рабочий стол
5. **В этот же момент** Windows Task Scheduler автоматически запускает `start-bot.bat` в фоне
6. Бот живёт, клиент может писать в Telegram

**Никаких окон, консолей, команд писать не нужно.** Всё в фоне.

## Когда бот НЕ работает

| Ситуация | Бот живой? | Что делать |
|---|---|---|
| Ноутбук выключен | ❌ Нет | Включить |
| Ноутбук в режиме сна | ❌ Нет | Разбудить (открыть крышку / двинуть мышь) |
| Ноутбук в гибернации | ❌ Нет | Включить |
| Нет интернета | ⚠️ Стартует, но не отвечает | Восстановить интернет |
| Windows работает | ✅ Да | — |
| Зашёл под другим пользователем | ❌ Задача под `Dell` | Войти под нужным пользователем |

## Как быстро проверить, что бот жив

**Вариант 1 — через Telegram (рекомендую):**
Открой своего бота в Telegram → напиши `/start` → если ответил с выбором языка — всё работает.

**Вариант 2 — через PowerShell:**

```powershell
Get-Process python
```

Если в списке есть строка `python` — процесс жив.

**Вариант 3 — посмотреть лог:**

Открой файл `C:\Users\Dell\Documents\project\service-upgrade-system\bot_logs.log` — последние строки покажут, что было.

## Управление задачей автозапуска

Все команды — в PowerShell.

| Команда | Что делает |
|---|---|
| `Start-ScheduledTask -TaskName ServiceUpgradeBot` | Запустить бота вручную (если упал) |
| `Stop-ScheduledTask -TaskName ServiceUpgradeBot` | Остановить задачу (не убивает уже запущенный процесс) |
| `Stop-Process -Name python -Force` | Убить процесс бота |
| `Get-ScheduledTaskInfo -TaskName ServiceUpgradeBot` | Когда последний раз запускался, результат |
| `Get-Process python` | Жив ли процесс |
| `Unregister-ScheduledTask -TaskName ServiceUpgradeBot -Confirm:$false` | Полностью удалить автозапуск |

## Что делать, если бот не отвечает в Telegram

Чек-лист по порядку:

1. **Проверить интернет** — открой любой сайт.
2. **Проверить, жив ли процесс:** `Get-Process python` в PowerShell. Если нет — переходи к п. 4.
3. **Если процесс жив, но бот не отвечает** — посмотри последние строки `bot_logs.log`. Скорее всего там ошибка от Telegram (rate limit, network).
4. **Перезапустить:**
   ```powershell
   Stop-Process -Name python -Force
   Start-ScheduledTask -TaskName ServiceUpgradeBot
   ```
5. Подожди 5–10 секунд → попробуй `/start` в боте.
6. **Если не помогло** — обратись к разработчику (Claude). У него есть правило авто-восстановления из GitHub.

## Куда приходят уведомления

Все уведомления (новый клиент, нажал «Я оплатил») приходят в Telegram пользователю с `ADMIN_ID = 898310868`.

При каждом «Я оплатил» открывай банковское приложение узбекской карты (VISA `4278 3200 2347 0544`, ANZHE), проверяй:

1. Поступила ли сумма (точно как указано в уведомлении)
2. Если поступила — пиши клиенту вручную и выдавай продукт
3. Если нет в течение 30 минут — связывайся с клиентом, уточняй


Или команда `/stats` боту (от админа) — покажет количество и сумму pending-заявок.

## Что НЕ делать

- ❌ Не удалять папку `service-upgrade-system\.git` — это история проекта
- ❌ Не коммитить `.env` (там токен и реквизиты карты)
- ❌ Не редактировать `bot.py` / `config.py` без понимания — может сломать запуск
- ❌ Не запускать `python bot.py` вручную, пока задача планировщика жива — словишь ошибку «бот уже запущен» (PID-lock)

## Если переехал на новый ноутбук

1. Клонировать репозиторий: `git clone https://github.com/irekgai111-lang/payment-bot.git`
2. Восстановить `.env` (вручную, по образцу `.env.example`)
3. Установить Python 3.12 и зависимости: `pip install -r requirements.txt`
4. Заново зарегистрировать задачу планировщика (см. `.claude/CLAUDE.md` → «Автозапуск»)
