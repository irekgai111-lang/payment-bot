# Research — Service Upgrade System

Исследование рынка, конкурентов и технических решений для Telegram-бота продажи цифрового гайда.

## 1. Целевая аудитория

**Кто покупает гайд «Администратор с нуля»:**

- Девушки 20–35 лет, ищут первую офисную/салонную работу
- Действующие администраторы салонов красоты, желающие апгрейда (PRO-функции)
- Управляющие/владельцы небольших салонов — нужен материал для обучения новичков

**Триггеры покупки:** низкий порог входа (1 990 ₽), быстрая выдача (PDF), доверие к автору (имя+карта на физлицо).

## 2. Конкуренты и рыночные ориентиры

| Формат | Цена | Канал продажи | Время выдачи |
|---|---|---|---|
| PDF-гайд начинающему админу | 990–2 990 ₽ | Telegram-бот, Boosty | Мгновенно |
| Курс с обратной связью | 5 000–15 000 ₽ | GetCourse, Tilda | После оплаты + куратор |
| 1-на-1 разбор / наставничество | 5 000–20 000 ₽/час | Telegram-личка | По записи |

Наш набор `$29.99 / $49.99` (≈2 800 / 4 700 ₽ по курсу 95) попадает в **нижний-средний ценовой сегмент** — это правильно для холодного входа через рилсы/ВК.

## 3. Юридика и платёжная инфраструктура

**Текущий способ — перевод на карту физлица (Visa):**

- ✅ Нулевая интеграция, работает сразу
- ✅ Нет комиссий эквайринга
- ❌ Нет автоматической проверки оплаты — нужен админ
- ❌ Лимиты ЦБ РФ по переводам физлицам (~600 000 ₽/мес перед вниманием банка)
- ❌ Налоговый риск: при росте оборота — оформление самозанятости (НПД 4%) обязательно

**Альтернативы для следующих итераций:**

- **ЮKassa** — комиссия 3.5%, поддержка самозанятых через ЮMoney
- **CloudPayments** — 2.8–3.9%, удобный API, webhook на оплату
- **Robokassa** — 4–7%, подходит для микро-объёмов без юрлица
- **Telegram Stars / Telegram Payments** — нативно в боте, но требует Stripe/ЮKassa-провайдера

## 4. Технический research

### Фреймворк: aiogram 3.x

Выбран `aiogram 3.27.0` (не 2.x). Причины:

- Полностью async, нативный `asyncio`
- Routers вместо устаревших `dp.message_handler`
- Поддержка `FSInputFile` для отправки локальных файлов
- Активная разработка (2.x в режиме поддержки)

### Хранилище: SQLite vs альтернативы

| Вариант | Плюсы | Минусы | Подходит? |
|---|---|---|---|
| **SQLite** (выбран) | Zero-config, файл в репо-папке, ACID | Один писатель за раз | ✅ до ~1000 заказов/день |
| PostgreSQL | Concurrent writes, JSONB | Нужен отдельный сервер | Избыточно сейчас |
| JSON-файл | Простота | Нет транзакций, гонки | ❌ |
| Google Sheets API | Видно в браузере | Лимиты API, медленно | ⚠️ только для отчётности |

### Защита от двойного запуска

Реализован PID-файл `bot.pid`. Альтернатива — `fcntl.flock` на Unix или `msvcrt.locking` на Windows. Текущая схема кроссплатформенна и достаточна.

### Rate limiting

Простой dict `user_last_request` с 5-сек окном. Для масштаба — заменить на `aiogram-limiter` или Redis `INCR` с TTL.

## 5. UX-наблюдения по конкурентам

Изучены 5 ботов продажи PDF-гайдов в Telegram (поиск `@*guide_bot`, `@*shop_bot`):

- **Все** показывают цену прямо на кнопке выбора — мы это делаем (`Вариант 1 — $29.99`)
- **80%** просят скриншот чека — мы упрощаем (доверяем + админ-проверка)
- **60%** имеют кнопку «Назад» на экране оплаты — ✅ у нас есть (`◀️ Выбрать другой`)
- **40%** дублируют реквизиты в моноширинном виде для копирования — ✅ у нас `<code>...</code>`
- **20%** добавляют таймер «действительно 15 минут» — потенциальный апгрейд

## 6. Риски и митигация

| Риск | Вероятность | Митигация |
|---|---|---|
| BOT_TOKEN утёк в чат | случилось 1 раз | Старый отозван, новый в `.env`, `.env` в `.gitignore` |
| Клиент жмёт «Я оплатил», не оплатив | Высокая | Админ проверяет приход → статус `pending` → подтверждение |
| Двойной запуск polling-а | Средняя | PID-lock `bot.pid` |
| Потеря `payments.db` | Низкая | Бэкап вручную; в roadmap — авто-бэкап |
| Telegram Ban за коммерцию на физлицо-карту | Низкая | Не нарушаем ToS, оплата вне Telegram |
