# User Flow — сценарий клиента

1. **Клиент жмёт `/start`**
   - Сохраняется в `users` (`first_seen_at`, `lang`)
   - При первом старте админу приходит «👤 Новый клиент» (повторные `/start` не дублируются)
   - Если язык не выбран — кнопки RU/EN; иначе сразу список продуктов

2. **Клиент выбирает продукт**
   - Видит описание + кнопку «💳 Оплатить — $X.XX»

3. **Клиент жмёт «💳 Оплатить»**
   - Создаётся заявка в `payments` со статусом `awaiting_receipt` и **уникальной суммой** (базовая цена минус случайные 0..29 центов)
   - Показывается: номер заявки `#ORDER-{id}`, точная сумма, реквизиты карты, просьба указать `#ORDER-{id}` в комментарии перевода
   - Кнопки: «✅ Я оплатил» / «❌ Отменить»

4. **Клиент жмёт «✅ Я оплатил»**
   - Бот просит скриншот чека (кнопка «⏭️ Пропустить» доступна)

5. **Клиент шлёт фото или жмёт «Пропустить»**
   - Статус заявки → `awaiting_review`
   - Админу приходит карточка с фото (или без), суммой, `user_id`, `#ORDER-{id}` и кнопками **✅ Подтвердить / ❌ Отклонить**

6. **Админ сверяет с банком**
   - Ищет входящий перевод на **ровно ту же сумму** (или с комментарием `#ORDER-{id}`)
   - Жмёт ✅ или ❌
   - Переход идемпотентный: повторный клик ничего не делает

7. **Клиент получает результат**
   - При ✅ → «Оплата подтверждена», админ связывается лично для выдачи продукта
   - При ❌ → «Оплата не подтверждена», номер поддержки

## Авто-истечение

Заявки в `awaiting_receipt` / `awaiting_review` старше 2 часов фоновая задача `ttl_worker` переводит в `expired` (раз в 5 мин). Их уникальные суммы возвращаются в пул.

## Что бот НЕ делает автоматически

- Не выдаёт продукт по клику «Я оплатил» — только админ через ✅
- Не принимает фото без активной заявки `awaiting_receipt` (отвечает hint-ом)
- Не уведомляет админа повторно при `/start` от того же пользователя
